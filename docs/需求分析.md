# 健身打卡系统 — 项目需求分析

## 1. 项目概述

### 1.1 项目名称

基于 Vue3 + Spring Boot 的健身打卡系统设计与实现

### 1.2 项目背景

随着全民健身意识的增强，越来越多人开始规律运动。然而，个人运动记录往往散落在笔记、聊天记录中，缺乏系统化管理。本系统旨在为用户提供一个简洁易用的健身打卡平台，帮助用户记录每日训练情况、查看运动统计数据，同时管理员可通过后台管理用户、打卡记录和发布公告。

### 1.3 项目定位

本系统为大专毕业设计项目，以展示 Vue3 + Spring Boot 技术应用为核心目标，功能完整但不追求企业级复杂度，代码清晰、易理解、可直接运行。

### 1.4 目标用户

| 角色 | 描述 |
|------|------|
| 普通用户 | 注册登录后记录个人健身打卡、查看统计数据和公告 |
| 管理员 | 管理用户、查看所有打卡记录、发布和管理公告、查看平台概览数据 |

## 3. 非功能性需求

### 3.1 性能要求

- 页面首屏加载时间不超过 3 秒
- 接口响应时间不超过 500ms（常规查询）
- 支持 50 并发用户同时访问

### 3.2 可用性要求

- 界面简洁直观，符合主流操作习惯
- 表单提供必要的输入校验与提示
- 操作成功/失败给出明确反馈

### 3.3 安全性要求

- 密码采用 MD5 加盐加密存储
- 使用 JWT 进行身份认证，Token 有效期 24 小时
- 前后端分离，后端接口进行统一的登录校验
- 管理员接口与用户接口分离，权限隔离

### 3.4 可维护性要求

- 代码结构清晰，分层明确
- 关键逻辑添加注释
- 前端采用组件化开发
- 接口遵循 RESTful 风格

### 3.5 兼容性要求

- 支持 Chrome、Edge 等主流浏览器最新版本
- 后端基于 JDK 8+，MySQL 5.7+

## 6. 数据流设计

### 6.1 用户端流程

```
注册 → 登录 → 首页（打卡概览）→ 健身打卡（增删改查）
                                    ↓
                              数据统计（图表展示）
                                    ↓
                              公告查看
```

### 6.2 管理端流程

```
管理员登录 → 后台首页（数据概览）
                ├── 用户管理（增删改查）
                ├── 打卡管理（查删）
                └── 公告管理（增删改查）
```

### 6.3 请求流程

```
浏览器 → Vue Router → 页面组件 → Axios 请求
    → Spring Boot Controller → Service → Mapper → MySQL
    → 响应返回 → Axios 拦截器处理 → 组件数据更新 → 页面渲染
```

## 7. 约束与限制

1. 不做第三方登录（微信、QQ等），仅使用系统内账号密码登录
2. 不接入 Redis 缓存，直接查询 MySQL
3. 不做文件上传到 OSS/MinIO，头像使用前端默认占位图
4. 不实现消息推送、邮件通知等功能
5. 不做移动端适配，仅面向桌面浏览器
6. 不做微服务拆分，单体应用即可
7. 管理员账号通过数据库初始化脚本预设，不提供开放注册
