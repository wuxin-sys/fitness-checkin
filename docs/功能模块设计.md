## 4. 模块详细设计

### 4.1 登录注册模块

**注册流程：**

```
填写注册信息 → 前端校验 → 提交请求
    → 后端校验用户名唯一性 → 密码加密 → 写入数据库 → 返回成功
```

**登录流程：**

```
填写用户名密码 → 提交请求
    → 后端校验账号密码 → 生成 JWT Token → 返回 Token + 用户信息
    → 前端存储 Token → 跳转首页
```

**Token 管理：**
- Token 存储在 `localStorage`
- Axios 请求拦截器自动携带 Token
- 响应拦截器检测 401，自动跳转登录页
- Token 过期时间：24 小时

---

### 4.2 健身打卡模块

**打卡规则：**
- 同一用户每天同种训练类型仅可打卡一次
- 打卡日期默认为当天，可修改为历史日期
- 修改打卡不改变 create_time

**打卡数据校验：**

| 字段 | 校验规则 |
|------|----------|
| 训练日期 | 必填，不能是未来日期 |
| 训练类型 | 必选，从枚举值中选择 |
| 训练时长 | 必填，1-600 分钟 |
| 消耗热量 | 必填，1-9999 千卡 |
| 备注 | 可选，最多 200 字 |

---

### 4.3 数据统计模块

**连续打卡天数算法：**
从今天往前逐日查询，直到找到中断的一天，连续天数即为计数结果。

**每月打卡趋势：**
查询近 6 个月每月的打卡次数，使用 ECharts 柱状图展示。

**训练类型占比：**
统计当前用户所有打卡记录中各训练类型的数量，使用 ECharts 饼图展示。

---

### 4.4 后台管理模块

**管理员认证：**
- 管理员使用独立的 `admin` 表认证
- 管理员登录后获得管理员 Token，与用户 Token 区分
- 后端通过拦截器校验管理员身份

**级联删除：**
- 删除用户时，同时删除该用户的所有打卡记录

## 7. 状态管理设计

### 7.1 Pinia Store

| Store | 职责 |
|-------|------|
| `useUserStore` | 用户登录状态、Token、用户信息 |
| `useAdminStore` | 管理员登录状态、Token、管理员信息 |

### 7.2 Store 数据流

```
登录成功 → store.setToken() → localStorage.setItem()
              ↓
         store.setUserInfo()
              ↓
         页面根据 store.token 判断登录状态
              ↓
         路由守卫检查 token → 未登录跳转 /login
```

### 8.2 路由守卫

```
router.beforeEach((to, from, next) => {
  if (to.meta.requiresAuth && !token) → next('/login')
  if (to.meta.requiresAdmin && !adminToken) → next('/admin/login')
  next()
})
```

## 9. 错误处理设计

### 9.1 前端错误处理

- Axios 响应拦截器统一处理 HTTP 错误
- 401 → 清除 Token → 跳转登录页
- 400 → 弹出错误提示（使用 Element Plus Message）
- 500 → 提示"服务器异常，请稍后重试"
- 网络错误 → 提示"网络连接失败"

### 9.2 后端异常处理

- 使用 `@RestControllerAdvice` 全局异常捕获
- 业务异常统一返回 400 + 错误描述
- 未捕获异常返回 500 + 通用错误信息
