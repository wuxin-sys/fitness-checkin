# 健身打卡系统 — 数据库设计

## 1. 数据库概述

- 数据库名称：`fitness_checkin`
- 字符集：`utf8mb4`
- 排序规则：`utf8mb4_general_ci`
- 存储引擎：`InnoDB`
- 数据表数量：4 张

## 3. 数据表详细设计

### 3.1 user（用户表）

| 字段名 | 类型 | 长度 | 允许空 | 默认值 | 说明 |
|--------|------|------|--------|--------|------|
| id | BIGINT | 20 | 否 | 自增 | 主键 |
| username | VARCHAR | 50 | 否 | — | 用户名，唯一 |
| password | VARCHAR | 100 | 否 | — | 密码（MD5 加盐加密） |
| nickname | VARCHAR | 50 | 是 | NULL | 昵称 |
| gender | TINYINT | 1 | 是 | 0 | 性别：0-未知 1-男 2-女 |
| phone | VARCHAR | 20 | 是 | NULL | 手机号 |
| role | TINYINT | 1 | 否 | 0 | 角色：0-普通用户 1-管理员 |
| avatar | VARCHAR | 255 | 是 | NULL | 头像地址 |
| create_time | DATETIME | — | 否 | CURRENT_TIMESTAMP | 创建时间 |

**索引：**

| 索引名 | 字段 | 类型 |
|--------|------|------|
| PRIMARY | id | 主键 |
| uk_username | username | 唯一索引 |

---

### 3.2 checkin（健身打卡表）

| 字段名 | 类型 | 长度 | 允许空 | 默认值 | 说明 |
|--------|------|------|--------|--------|------|
| id | BIGINT | 20 | 否 | 自增 | 主键 |
| user_id | BIGINT | 20 | 否 | — | 用户 ID，关联 user.id |
| checkin_date | DATE | — | 否 | — | 打卡日期 |
| sport_type | VARCHAR | 20 | 否 | — | 训练类型 |
| duration | INT | 11 | 否 | 0 | 训练时长（分钟） |
| calorie | INT | 11 | 否 | 0 | 消耗热量（千卡） |
| remark | VARCHAR | 200 | 是 | NULL | 备注 |
| create_time | DATETIME | — | 否 | CURRENT_TIMESTAMP | 创建时间 |

**训练类型枚举值：**

| 值 | 说明 |
|----|------|
| 跑步 | 跑步 |
| 胸部 | 胸部训练 |
| 背部 | 背部训练 |
| 腿部 | 腿部训练 |
| 肩部 | 肩部训练 |
| 有氧 | 有氧训练 |
| 其他 | 其他训练 |

**索引：**

| 索引名 | 字段 | 类型 |
|--------|------|------|
| PRIMARY | id | 主键 |
| idx_user_id | user_id | 普通索引 |
| idx_user_date | user_id, checkin_date | 联合索引 |
| idx_checkin_date | checkin_date | 普通索引 |

**业务约束（应用层保证）：**
- 同一用户同一天同一训练类型只能有一条打卡记录（`user_id + checkin_date + sport_type` 唯一组合）

## 4. 数据表关系

```
admin ──（独立）──> 管理系统

user ── 1:N ──> checkin
  │               user_id 外键关联
  │               级联删除：删除用户时同步删除其打卡记录
  │
  └──（读取）──> notice（用户查看公告，无外键关联）

admin ──（管理）──> user
admin ──（管理）──> checkin
admin ──（管理）──> notice
```

## 6. 索引设计说明

| 索引 | 原因 |
|------|------|
| `uk_username` (user) | 用户名登录查询 + 唯一性校验 |
| `idx_user_id` (checkin) | 按用户查询打卡记录 |
| `idx_user_date` (checkin) | 查询某用户某日期范围的打卡（首页概览、统计） |
| `idx_checkin_date` (checkin) | 管理员按日期查询打卡 |
| `uk_username` (admin) | 管理员登录查询 |

## 7. 字段设计说明

### 7.1 密码存储

```
存储格式：MD5(MD5(password) + salt)
salt：固定字符串 "fitness_checkin_salt"
```

> 使用双层 MD5 + 固定盐，满足毕业设计安全要求，不引入额外依赖。

### 7.2 头像处理

- 不实现文件上传，`avatar` 字段预留
- 前端使用 Element Plus 默认头像图标
- 后续如需扩展可接入文件上传

### 7.3 日期时间

- `create_time` 使用 `DATETIME` 类型，默认 `CURRENT_TIMESTAMP`
- `checkin_date` 使用 `DATE` 类型，仅存日期不存时间
- 所有时间以数据库服务器时间为准
