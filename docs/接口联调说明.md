# 健身打卡系统 — 接口联调说明

## 1. 联调前置条件

### 1.1 环境要求

| 组件 | 版本 | 说明 |
|------|------|------|
| JDK | 1.8+ | 编译运行后端 |
| Maven | 3.6+ | 后端构建 |

```bash

# 4. 启动前端（在 fitness-web 目录，新开终端）

npm run dev
```

## 2. 前后端对接架构

```
浏览器 (localhost:5173)
    │
    ▼
Vite Dev Server (port 5173)
    │  /api/* 请求 → proxy
    ▼
Spring Boot (port 8080)
    │  JWT 拦截器 / Admin 拦截器
    ▼
Controller → Service → Mapper → MySQL
```

### 2.1 代理配置

Vite `vite.config.js` 中配置了代理：

```js
proxy: {
  '/api': {
    target: 'http://localhost:8080',
    changeOrigin: true
  }
}
```

所有前端 `/api/*` 请求自动转发到后端 `localhost:8080`。

### 2.2 Axios 实例

前端维护两个独立的 Axios 实例：

| 实例 | baseURL | 用途 | Token 来源 |
|------|---------|------|-----------|
| `request` | `/api` | 用户端接口 | `localStorage.token` |
| `adminRequest` | `/api/admin` | 管理端接口 | `localStorage.adminToken` |

每个实例都有自己的请求/响应拦截器，自动携带 Token 并处理 401 跳转。

## 4. 数据格式约定

### 4.1 统一响应

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { ... }
}
```

### 4.2 分页响应

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "records": [ ... ],
    "total": 25,
    "size": 10,
    "current": 1,
    "pages": 3
  }
}
```

前端统一使用 `res.data.records` 和 `res.data.total` 取值。

### 4.3 日期格式

- 打卡日期 `checkinDate`：`"2026-07-06"`（`YYYY-MM-DD` 字符串）
- 创建时间 `createTime`：`"2026-07-06 14:30:00"`（ISO 格式）

## 5. 联调中已修复的问题

### 5.1 拦截器路径冲突

**问题：** 管理员调用 `/api/admin/*` 时，JWT 拦截器（拦截 `/api/**`）先于 Admin 拦截器执行，因管理员没有用户 Token 导致 401。

**修复：** 在 `WebConfig` 中，JWT 拦截器新增排除路径 `/api/admin/**`：

```java
registry.addInterceptor(jwtInterceptor)
    .addPathPatterns("/api/**")
    .excludePathPatterns(
        "/api/user/login",
        "/api/user/register",
        "/api/admin/**"    // ← 新增：排除管理员接口
    );
```

## 6. 常见问题排查

### 6.1 前端启动后页面空白

- 检查 `npm install` 是否执行成功
- 检查浏览器控制台是否有 JS 报错
- 确认 `vite.config.js` 中 proxy 配置正确

### 6.2 登录接口返回 404

- 确认后端已启动（`http://localhost:8080`）
- 检查 `application.yml` 中 `server.port` 是否为 8080

### 6.3 登录成功但后续请求 401

- Token 可能过期（默认 24 小时），清除 localStorage 后重新登录
- 检查 Axios 拦截器是否正确携带了 `Authorization` 头

### 6.4 数据库连接失败

- 确认 MySQL 已启动
- 确认 `fitness_checkin` 库已创建
- 检查 `application.yml` 中数据库用户名密码是否正确

### 6.5 管理员登录后接口 403

- 如果是旧代码，检查 `WebConfig` 是否包含 `/api/admin/**` 的排除配置
- 确认已按第 5.1 节修复拦截器冲突
